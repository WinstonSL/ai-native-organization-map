# Project Context

## Why this project exists

The user is building a long-term learning track around one question:

> How does AI enter teams and organizations, become real labor and infrastructure, and eventually help transform the organization into an AI-native organization?

The project emerged after exploring product forms such as agent-native workspaces, AI teammates, multi-agent systems, agent harness/runtime infrastructure, memory layers, agent governance, and agentic workflow systems.

## User learning characteristics

The user works in operations rather than software development. Many technical concepts are new. The user does not want a traditional computer-science curriculum; they want enough technical depth to understand how modern AI products and organizational systems actually work.

A critical UX requirement is cognitive orientation. Long chat-style waterfall explanations are hard to retain. The map must therefore answer three questions at all times:
- Where am I in the overall system?
- What does this concept connect to?
- What concrete product or pattern can I study next?

## Strategic learning goal

The target expertise is not "how to build one agent".

The target expertise is:

**how to turn AI agents into durable organizational capability.**

This includes work redesign, organizational context, human-agent collaboration, governance, evaluation, operating models, and change management.

## Key conclusions already established

### 1. Workflow is central
The most important enterprise problem is not adding AI to an old process, but redesigning the process around human + agent capabilities.

### 2. Context is infrastructure
Memory is broader than chat history. Organizations need systems that deliver the right historical, business, policy, task, and real-time context to the right agent at the right time.

### 3. Workspace is more than UI
An agent-native workspace must represent shared files, tasks, context, state, history, interventions, and permissions for both humans and agents.

### 4. Multi-agent is not automatically better
Multi-agent is a coordination architecture. A single strong agent + tools/skills may be better for many tasks. Learn orchestration patterns and trade-offs rather than treating agent count as progress.

### 5. Governance and AgentOps are core enterprise layers
At scale, agents need identity, owners, permission policies, registries, approvals, evaluation, observability, lifecycle management, and retirement.

### 6. Organization design is the destination
The learning map ultimately asks how roles, decision rights, management spans, workflows, and operating models change when AI becomes a real organizational actor.

## Product-analysis heuristic

When a new AI product appears, do not first ask "does it have agents?"

Ask:
1. What is the first-class object?
2. What persistent state does it own?
3. What work does it execute vs coordinate?
4. What is deterministic vs agentic?
5. Where does context live?
6. How do humans intervene?
7. What is the permission/governance model?
8. Does it change the organization or simply add an assistant to existing software?
